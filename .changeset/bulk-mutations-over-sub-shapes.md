Bulk mutations on the generic query plane (`deleteAll`, `deleteWhere`, `update().forAll()` and `update().where()`) are authorized over every sub-shape they reach. They change every instance of the root shape's class and of its subclasses, so the access check now maps them to the root shape plus every registered shape whose target class is in `subClassesOf(root class)` (from `@_linked/core/ontology/classHierarchy`), and the rule of each of those stores must allow the mutation; a function rule sees the sub-shapes in `ctx.shapes`. A bulk mutation whose root and sub-shapes route to more than one store is refused with `ServerCallError(409, 'bulk-mutation-spans-stores: …')` instead of being applied to one store only. Shapes and stores are now resolved in the query's shape catalog, as `LinkedStorage` routes the query, for every generic-plane query: a query lowered in a catalog is judged by the rule of the store it actually runs on (a shape IRI pinned globally but resolved in a catalog now maps to the store the catalog routes it to, usually the default dataset). Needs a `@_linked/core` that exports `@_linked/core/ontology/classHierarchy`.
